# pulse — домовленості проєкту

## Межі шарів

Кожен шар знає лише про сусіда знизу. Порушення цього — головна помилка в такому проєкті.

| Шар | Знає | Не знає **ніколи** |
|---|---|---|
| `sources/*.py` | формат свого джерела | що існує база; що існують інші джерела |
| `model.py` | нічого, це просто форма | усе |
| `db.py` | таблиці, збереження без дублів | що бувають HTML, RSS, CSV |
| `analytics.py` | як рахувати з канонічних записів | звідки записи взялися |
| `report.py` | як скласти контракт | формати джерел |
| `__main__.py` | як покликати перше й останнє | решту |

Імпорти йдуть тільки вниз. Якщо в `db.py` знадобився `bs4` — щось пішло не так.

## Залізні правила

1. **`None` — це «даних немає». Ніколи не `0` і не `""`.** Різниця має дожити до JSON
   як `null`. Це прямий критерій оцінювання.
2. **Час у програмі — tz-aware UTC.** У SQLite лягає naive UTC; конвертація живе рівно
   в одному місці — `UtcDateTime` у `db.py`. Більше ніде `replace(tzinfo=...)` для
   зберігання не робиться.
3. **Дати без зони перераховуються через назву зони**, не через фіксований зсув
   (`ZoneInfo("Europe/Kyiv")`, не «+3»). Влітку Київ +3, взимку +2.
4. **Ключ — `(source, external_id)`.** Унікальність `external_id` у межах джерела
   забезпечує адаптер, а не сховище.
5. **Вид метрики оголошується в адаптері** (`metric_name`, `metric_precision`), а не
   пишеться в кожен рядок таблиці.
6. **Адаптер не дедуплікує.** Він віддає все, що прочитав; схлопування за ключем — робота
   `save_posts`.
7. **Придатність рядка — за наявністю обов'язкових полів**, не за кількістю колонок.
   Обов'язкові: `external_id`, `channel`, `published_at`.
8. **Непридатний рядок іде в `rejected_rows`**, а не зникає. Кількість відкинутих
   потрапляє у звіт.
9. **Поле потрапляє в модель, лише якщо можна назвати, хто його читає.**
10. **Вивід у консоль — примусово UTF-8** (`sys.stdout.reconfigure`). Windows-консоль
    буває в cp1252/cp866, де українських літер немає, і `print` падає.

## Як додати джерело

Новий файл у `pulse/sources/` + один рядок у `pulse/sources/registry.py`. Більше нічого.
Якщо довелося правити `model.py`, `db.py`, `analytics.py` чи `report.py` — рішення
неправильне, треба переробити адаптер.

Договір адаптера — `pulse/sources/base.py`: атрибути `name`, `metric_name`,
`metric_precision`, методи `can_handle(path)` і `parse(path) -> ParseResult`.

Реєстр — **явний список**, автопошуку файлів не додавати: список має бути видно очима.

## Тести

- `pytest`, **без мережі** — це стоп-фактор оцінювання;
- у тестах, що залежать від періоду, `--until` фіксований, щоб результат не залежав
  від дати запуску;
- кожен адаптер має тест на свої крайні випадки (немає метрики, немає тексту, репост,
  побитий рядок, два формати дат);
- ідемпотентність перевіряється подвійним імпортом фікстур.

## Команди

```bash
python -m pulse import fixtures/
python -m pulse report --days=30 --until=latest
pytest
```

`--until` за замовчуванням «зараз». Значення `latest` — найсвіжіша дата **з бази**.
Фікстури липневі, тому `--days=30` без `--until` чесно дає порожній зріз.
