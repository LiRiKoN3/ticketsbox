# pulse — домовленості проєкту

## Межі шарів

Кожен шар знає лише про сусіда знизу. Порушення цього — головна помилка в такому проєкті.

| Шар | Знає | Не знає **ніколи** |
|---|---|---|
| `sources/*.py` | формат свого джерела | що існує база; що існують інші джерела |
| `model.py` | нічого, це просто форма | усе |
| `db.py` | таблиці, збереження без дублів | що бувають HTML, RSS, CSV |
| `analytics.py` | як рахувати з канонічних записів | звідки записи взялися |
| `report.py` | як скласти контракт | формати джерел |
| `__main__.py` | як покликати перше й останнє | решту |

Імпорти йдуть тільки вниз. Якщо в `db.py` знадобився `bs4` — щось пішло не так.

## Залізні правила

1. **`None` — це «даних немає». Ніколи не `0` і не `""`.** Різниця доживає до JSON як
   `null`. Це прямий критерій оцінювання.
2. **Час у програмі — tz-aware UTC.** Конвертація живе рівно в одному місці —
   `UtcDateTime` у `db.py`. Більше ніде `replace(tzinfo=...)` для зберігання.
3. **Дати без зони — через назву зони** (`ZoneInfo("Europe/Kyiv")`), не через «+3»:
   влітку Київ +3, взимку +2.
4. **Ключ — `(source, external_id)`.** Унікальність забезпечує адаптер, причому **між
   усіма файлами** джерела: `guid` з RSS унікальний лише в своїй стрічці, тому адаптер
   додає до нього хост стрічки.
5. **Вид метрики оголошується в адаптері** (`metric_name`, `metric_precision`), а не
   пишеться в кожен рядок таблиці.
6. **Адаптер не дедуплікує** — схлопування за ключем робить `save_posts`.
7. **Придатність рядка — за наявністю обов'язкових полів** (`external_id`, `channel`,
   `published_at`), не за кількістю колонок.
8. **Бруд буває двох видів, і обидва передбачені** — «поля немає» і «поле є, але воно
   сміття». Нечитабельне обов'язкове поле відкидає рядок, необов'язкове дає `None`,
   нечитабельний файл іде цілком (`line_number = 0`). Виняток з адаптера — його помилка.
9. **Нічого не зникає мовчки.** Непридатне йде в `rejected_rows`; кожен файл фіксується
   окремим `commit`, щоб збій не відкотив прочитане; лічильник показує **поточний стан**
   — при повторному читанні файлу старі відомості про його брак стираються.
10. **Округлення — справа `report.py`, не `analytics.py`.** Прапорці рахуються з точного
    значення, інакше брешуть в околі межі.
11. **Поле потрапляє в модель, лише якщо можна назвати, хто його читає.**
12. **Говори з людиною зрозуміло.** Вивід — примусово UTF-8 (`sys.stdout.reconfigure`),
    бо Windows-консоль буває в cp1252/cp866. Помилка у вводі — зрозумілий рядок і код
    виходу 2, а не traceback: мовчазний успіх гірший за помилку.

## Як додати джерело

Новий файл у `pulse/sources/` + один рядок у `pulse/sources/registry.py`. Більше нічого.
Якщо довелося правити `model.py`, `db.py`, `analytics.py` чи `report.py` — рішення
неправильне, треба переробити адаптер.

Договір — `pulse/sources/base.py`: атрибути `name`, `metric_name`, `metric_precision`,
методи `can_handle(path)` і `parse(path) -> ParseResult`. Там же спільне: `Unreadable`
і `reason_of` (причини відмови), `format_offset` (підпис зони), `WHOLE_FILE`.

Реєстр — **явний список**, автопошуку файлів не додавати: список має бути видно очима.

## Тести

- `pytest`, **без мережі** — це стоп-фактор оцінювання;
- у тестах, що залежать від періоду, `--until` фіксований;
- кожен адаптер має тест на свої крайні випадки; бруд виду «поле є, але воно сміття»
  зібраний окремо в `tests/test_broken_input.py`;
- тест, який фіксує неправильну поведінку, переписується разом із виправленням — код
  під тест не підганяється;
- ідемпотентність перевіряється подвійним імпортом фікстур.

## Команди

```bash
python -m pulse import fixtures/
python -m pulse report --days=30 --until=latest
pytest
```

`latest` — найсвіжіша дата **з бази**. Фікстури липневі, тому `--days=30` без `--until`
чесно дає порожній зріз.
